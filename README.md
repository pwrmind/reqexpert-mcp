# ReqExpert MCP

> Headless-движок управления требованиями с экспертной системой контроля качества, доступный через [Model Context Protocol](https://modelcontextprotocol.io).

ReqExpert MCP превращает классическую практику работы с требованиями (SRS, MoSCoW, критерии приёмки, атомарность, неоднозначность) в **детерминированный API для LLM**. Движок работает как «линтер» для ИИ: он не даёт модели галлюцинировать о качестве требования, а возвращает строгий структурированный вердикт по базе экспертных правил.

Используется в Claude Desktop, Cursor, VS Code и любом другом MCP-клиенте.

## Возможности

- **Headless-ядро** — никакого HTML/UI. Чистый TypeScript-движок на Node.js, пригодный для встраивания в любые сценарии.
- **Экспертная система с песочницей** — JS-правила выполняются в изолированном контексте `node:vm` с жёстким таймаутом 100 мс.
- **Автоматическая валидация** — каждое новое или изменённое требование мгновенно прогоняется через активные правила и получает оценку качества (0–100 %).
- **Граф зависимостей** — реальный impact-анализ вместо случайной оценки: прямые зависимые требования, связи по источнику, оценка риска.
- **Автогенерация ID** — `FR-XXX` / `NFR-XXX` / `REQ-XXX` без коллизий при удалении.
- **Генерация артефактов** — SRS в Markdown прямо из состояния проекта.
- **Атомарная запись** — состояние сохраняется через `tmp`-файл и `rename`, чтобы не терять данные при падении.
- **Схемы на Zod** — одна и та же схема валидирует данные внутри движка и описывает `inputSchema` для MCP-инструментов.

## Установка

Требования: **Node.js ≥ 20**.

```bash
git clone https://github.com/<ваш-логин>/reqexpert-mcp.git
cd reqexpert-mcp
npm install
npm run build
```

Проверка запуска через MCP Inspector:

```bash
npx @modelcontextprotocol/inspector node dist/index.js
```

Inspector откроет веб-интерфейс (обычно `http://localhost:6274`), где можно вручную вызвать любой инструмент и посмотреть список ресурсов.

## Подключение к MCP-клиенту

### Claude Desktop

Файл конфигурации:
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "reqexpert": {
      "command": "node",
      "args": ["C:\\projects\\ts\\reqexpert\\dist\\index.js"],
      "env": {
        "REQEXPERT_WORKSPACE": "C:\\projects\\my-project"
      }
    }
  }
}
```

### Cursor

Файл `.cursor/mcp.json` в корне проекта:

```json
{
  "mcpServers": {
    "reqexpert": {
      "command": "node",
      "args": ["/абсолютный/путь/к/reqexpert-mcp/dist/index.js"],
      "env": {
        "REQEXPERT_WORKSPACE": "/абсолютный/путь/к/вашему/проекту"
      }
    }
  }
}
```

### Переменные окружения

| Переменная             | Назначение                                                                 |
| ---------------------- | -------------------------------------------------------------------------- |
| `REQEXPERT_WORKSPACE`  | Директория, в которой будет создан `.reqexpert/project.json`. По умолчанию — `process.cwd()`. |

> 💡 Указывайте `REQEXPERT_WORKSPACE` на корень **вашего** проекта, а не на директорию MCP-сервера. Тогда файл `.reqexpert/project.json` можно коммитить в Git вместе с кодом.

## Инструменты (Tools)

| Инструмент           | Назначение                                                                 |
| -------------------- | -------------------------------------------------------------------------- |
| `add_requirement`    | Создать требование, авто-присвоить ID и провалидировать по всем активным правилам. |
| `update_requirement` | Обновить поля существующего требования и повторно прогнать экспертизу.     |
| `check_ambiguity`    | Быстрый линтер произвольного текста по правилу D26 («быстро», «удобно», …). |
| `analyze_impact`     | Граф зависимостей + оценка риска изменения требования.                     |
| `add_stakeholder`    | Зарегистрировать заинтересованное лицо.                                    |
| `add_expert_rule`    | Добавить новое JS-правило в базу знаний проекта.                          |

Все мутирующие инструменты возвращают расширенный контракт:

```json
{
  "requirement": { "...": "..." },
  "qualityScore": 40,
  "validationPassed": false,
  "violations": [
    {
      "ruleId": "D26",
      "ruleName": "Проверка неоднозначных терминов",
      "pass": false,
      "message": "Найдено терминов: 1",
      "issues": ["Неоднозначный термин \"быстро\". Укажите точное время отклика (например, \"< 2 сек\")"]
    }
  ]
}
```

Такой формат позволяет LLM **сразу видеть**, что нарушено, и исправлять формулировку итеративно.

## Экспертные правила

Встроены при первом запуске (файл `src/domain/presets.ts`):

### D25 — Атомарность

Требование должно описывать одну функциональность. Проверяются союзы (« и », «, а также », «, кроме ») и длина описания (> 3 предложений).

### D26 — Неоднозначность

Поиск субъективных и неизмеримых терминов: `быстро`, `удобно`, `иногда`, `часто`, `простой`, `легко`. Для каждого — конкретная рекомендация по замене.

### H78 — Критерии приёмки

Требование обязано содержать `acceptanceCriteria` длиной не менее 20 символов.

### Свои правила

Добавляются через `add_expert_rule`. Контракт:

```ts
{
  id: string;                 // например "CUSTOM-01"
  name: string;
  type: string;
  description: string;
  checkLogic: string;         // тело JS-функции вида function (requirement) { ... }
  example?: string;
  strictness?: 'low' | 'medium' | 'high';
  category?: string;
  active?: boolean;
}
```

`checkLogic` исполняется в `node:vm` со следующими ограничениями:
- нет доступа к `process`, `require`, `fs`, сети;
- жёсткий таймаут 100 мс;
- возвращаемое значение — `{ pass: boolean, message: string, issues: string[] }`.

## Формат хранения данных

Один файл — `.reqexpert/project.json` в корне рабочей директории:

```json
{
  "projectName": "My Project",
  "requirements": [ /* ... */ ],
  "stakeholders": [ /* ... */ ],
  "businessRules": [ /* ... */ ],
  "expertRules": [ /* D25, D26, H78, ... */ ],
  "activities": [
    { "type": "requirement", "message": "Добавлено требование FR-001", "timestamp": 1730000000000 }
  ]
}
```

Файл создаётся автоматически при первом вызове любого инструмента. Рекомендуется коммитить его в Git — так история требований живёт рядом с историей кода.

## Структура проекта

```

├── core/
│   ├── schema.ts          # Zod-схемы и TS-типы (единый контракт данных)
│   ├── rule-sandbox.ts    # Изолированное исполнение JS-правил через node:vm
│   └── store.ts           # Файловое хранилище (.reqexpert/project.json)

│   ├── engine.ts          # Класс ReqExpertEngine — фасад над всеми операциями
│   └── presets.ts         # Встроенные правила (D25, D26, H78)
└── index.ts               # MCP-сервер: регистрация Tools и Resources
```

## Пример использования

**Пользователь в чате Claude:**

> Добавь требование: «Система должна быстро авторизовывать пользователя».

**LLM вызывает `add_requirement`** → движок:

1. Создаёт `FR-001`.
2. Запускает D25, D26, H78.
3. Возвращает:

```json
{
  "requirement": { "id": "FR-001", "title": "Система должна быстро авторизовывать пользователя", "...": "..." },
  "qualityScore": 10,
  "validationPassed": false,
  "violations": [
    {
      "ruleId": "D26",
      "message": "Найдено терминов: 1",
      "issues": ["Неоднозначный термин \"быстро\". Укажите точное время отклика (например, \"< 2 сек\")"]
    },
    {
      "ruleId": "H78",
      "message": "Проблемы с критериями приемки",
      "issues": ["Отсутствуют критерии приемки (acceptanceCriteria)"]
    }
  ]
}
```

**LLM автоматически** предлагает переписать требование и, получив согласие, вызывает `update_requirement` с уточнёнными данными:

```json
{
  "id": "FR-001",
  "title": "Система должна авторизовывать пользователя не более чем за 2 секунды",
  "acceptanceCriteria": "Время от нажатия «Войти» до отображения главного экрана не превышает 2 с при нагрузке до 1000 RPS."
}
```

**Движок возвращает** `qualityScore: 60`, `validationPassed: true`.
